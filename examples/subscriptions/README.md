# Agentic OLAP · 订阅历史归属与七日使用对象

本应用从自含 DuckDB 原始历史、使用事件、真实日历和目的地关联出发，通过正式远程 MCP 完成调查、共享定义建设、上下文采用、发布、查询和结果消费。Kotlin 准备者产生业务数据与纯类型化作者定义模板，独立 Kotlin 客户端提交作者程序并消费正式回执。客户端不读取服务器文件或搬运私有发布。定义和独立业务预期由示例作者给出，不代表模型自主成绩。

## 历史与来源含义

旧系统按分记录存量，新系统按元记录。来源权威于 `2026-04-01` 切换：旧来源只负责切换日前的观察版本，新来源只负责切换日起的版本。旧库仍保留 S1 四月的陈旧 140 元对应记录；它不因存在于源中就取得四月来源权威。正式 `Scale` 单位方程将分乘以精确 `0.01` 转为 CNY 元，然后合并各自负责的记录。两源原始金额为 `DECIMAL(18,2)`；分换元、集合合并及存量汇总使用 `DECIMAL(38,4)`，保留换算产生的四位小数，整个链路采用精确算术、禁止隐式舍入。

| 订阅 | 三月存量 | 四月存量 | 三月区域 | 四月区域 |
| --- | ---: | ---: | --- | --- |
| S1 | 100 | 150 | 东 | 南 |
| S2 | 50 | 50 | 东 | 东 |

每次调用先按订阅选择不晚于 `as_of` 的最后一个真实存量版本，同一天存在并列版本则拒绝。区域历史独立选择同一 `as_of` 下的最后版本，再与已选存量关联。区域筛选不能提前替代版本选择，否则可能把 S1 的旧区域状态留下。缺失归属不推断，未知金额不补零。

三个采用引用同一个通用存量定义，分别固定时点与分组：

| 采用 code | 固定含义 | 预期结果（CNY 元） |
| --- | --- | --- |
| `march_regions` | 三月末，按历史区域分组 | 东 150 |
| `april_regions` | 四月末，按历史区域分组 | 东 50，南 150 |
| `april_total` | 四月末，不按区域分组 | 200 |

定义身份、采用身份与实例身份由各自正式 owner 产生。调用使用发布候选返回的实例，不以共享定义 ID 代替采用，也不能覆盖采用已固定的实参。存量只在同一明确观察点跨订阅合计，三月与四月不能相加成期间收入。

## 使用事件与日历

原始使用事件为三月一日 D、三月二日 A/B、三月八日 A/C，全部属于租户 T1。完整用户身份是 `(tenant, person)`。A 在两个日期出现，仍只算一个对象。

`seven_day_people` 使用真实日历作为日期人口，按日期 LEFT 关联原始使用事件。共同 `ObserveWindow` 先保留观察范围 `[2026-03-02, 2026-03-09)`，按公历日计算包含当日的六日向前窗口，再将展示范围裁为三月八日。完整元组精确去重结果为 **3**（A/B/C）。不能把两天各 2 人相加成 4，也不能带入三月一日 D。

日历是实际治理和采用的成员来源；精确发布固定其语义定义，执行仍读取实际业务表。执行在同一事务内核对其日期非 NULL、唯一及请求观察范围的完整覆盖；缺少日期是覆盖失败。日历中无业务观察的日期保留 LEFT 匹配的 NULL 用户字段，不生成使用事件或虚构对象。完整用户元组的任一字段为 NULL 时，不把它当成已知对象。这里使用公历日 RANGE，不能换成前六行或固定秒数后仍声称同一含义。同一展示日期的 RANGE peers 共享同一窗口结果，最终按该日期取 MAX 只收拢重复显示位置，未将去重计数重新求和。

## 完整日历日均

`calendar_daily_mean`观察三月2日至8日的完整七个公历日。真实日历LEFT关联使用事件，再逐日`COUNT`已匹配的事件身份；三月2日与8日各2次，其余5日为0。0来自明确的空匹配COUNT语义，没有补造使用记录。共同`ObserveWindow`在完整CALENDAR总体上计算AVG，展示三月8日结果 **4/7，约0.5714285714次/日**。

分母来自真实、唯一且覆盖观察范围的日历总体，不是写死除以7，也不是只除以有事件的两天。日历缺日属于覆盖失败。日均声明有限评价域、64位原生浮点与1e-9容差；历史存量的精确十进制合同保持独立。

## 目的地分摊

`subscription_charges`保存独立、明确可加的确认账款：S1为150，S2为50。可复用计算先按完整订阅身份完成账款测量，再供`allocated_destinations`继续组合。`subscription_destinations`保存真实订阅与目的地关系，`(subscription,destination)`在源表中非NULL且唯一：S1关联东和西，S2只关联东。分摊定义关联完整目的地总体，以`UNIFORM_ALLOCATION`按各订阅的实际关联成员数均分，最后按目的地合计。

S1的150在两个目的地各分75；S2的50全分到东，因此 **东125、西75，合计200**。分摊声明完整源对象身份和关联成员身份，分母不是全部目的地数，也不是JOIN后的任意行数。分配完成后才进行目的地报告；不能提前筛东后让S1在东取得150。

来源切换、历史区域与历史存量形成分别是独立共享`MEMBER_DEFINITION`。主题域采用这些规则时绑定自己的真实来源；历史余额、完整对象窗口、日均和账款目的地分摊又作为可复用计算定义，由同一正式发布提供普通测量调用。历史存量与确认账款各自具有独立来源和数量含义；本例的合法账款分摊不证明任意历史派生量都可再分摊。

## 运行与调用

在仓库根准备 JDK 21；输出目录必须不存在。

```sh
./project/gradlew -p project :development:subscriptions
```

Gradle 装配同轮 JVM 发行，以真实插件准备原始表，再由独立 Kotlin 研发客户端持有自己的 HTTPS JWKS、签名者和发行服务。它通过 MCP 建设、发布和执行，核对重启后的元数据、保存查询、结果和使用记录，并观察无来源读取旧结果。源文件在只读调用前后保持相同哈希。默认输出到 `.tmp/subscriptions`，可用 `-Partifacts=/absolute/path` 指定。

`tools/src/main/kotlin` 中的客户端通过 MCP 提交 [main.olap.kts](main.olap.kts)，由程序逐层创建实际物理采用、逻辑字段、事件、共同维度、成员规则、计算定义与上下文采用。发布后查询使用正式返回的实例身份；查询作者组织正式类型构成的完整 Query 和独立预期，程序通过客户端调用能力与分页读取结果。编译、SQL 执行与数量合同由服务承担。

日常业务Agent连接实际服务见[AI使用指引](../../docs/agent-usage.md)，来源、外部issuer、授权与预算配置见[服务使用说明](../../skills/agentic-olap/references/server.md)。

`http/report.json` 保存建设、重启和无来源读取旧结果等阶段的正式脚本回执，包含保存查询和结果的精确引用。`mcp-calls.jsonl` 保存所有阶段的实际 MCP 请求与响应；其中 `execute-script` 请求保留本次完整作者程序。服务重启后，将原回执中的精确引用作为参数提交同一程序的 `reopen` 分支。结果保留原生类型、单位和 NULL 含义；保存与查询复用分别是明确操作，不自动提升业务定义、换版本、补零或扩大预算。
